# 对照评测

`questions.json` 固定 72 题及原始文档证据，源提交为 `417fc690834fbc4406f48e503f5ef1f832d495db`。每题包含期望状态、原因、关键词、所需原文路径/行号/引文、最少图跳数和空白的人工正确性字段。

工程回归测试与检索评测分开。`tests/` 的模型替身只检查生命周期和证明约束；真实运行通过 `scripts/evaluate.py`，使用 BGE 512 维模型、同一 SQLite 快照、同一校区过滤、同一 12000 字符证据预算。`vector` 只做向量检索，不调用 BM25 或图遍历。

运行时需停掉 API；否则数据目录锁会拒绝第二个实例。默认输出 `evaluation/results.json`，该路径被 git 忽略。仓库中的 `reference-run.json` 是本机真实模型运行结果，包含全部响应，便于复核；不要将它当作其他机器的性能保证。

指标说明：

- **关键词检查代理指标**：状态/原因匹配且答案中出现所有标注词，不等于人工判断答案正确率。
- **完整必要证据覆盖率**：可回答题中，返回答案且全部必要原文行与引文被覆盖的题数 / 可回答题数。两种模式都按原文证据检查，不因 vector 没有图路径而直接判零。
- **图证明完整性**：另存逐题 `complete_graph_proof`，检查最少跳数和交集双分支；vector 没有图证明。
- **不可回答问题拒答率**：应拒答题中实际拒答的比例，和澄清题分开统计。
- **延迟**：模型预热后逐题墙钟时间，包含解析、检索和回答，不含冷启动/首次下载。
- **内存**：逐题采样 RSS；Windows 同时记录进程 `peak_wset`（如可用）。两模式在同一进程中顺序运行，内存数字不能当作独立模式峰值比较。目标 8GB/16GB 笔记本需自行重复测量。
- **人工正确率**：`human_answer_accuracy=null`，由测试同学独立审核后填写。答案支持、错误外推及是否答到问题都应审核。

这是开发集，包含用于开发和回归的问题；不是独立盲测集。开发中发现的失败题保留并修复了相应通用逻辑，不能将开发集分数用作未见问题上的性能承诺。建议另行留出新题用于课程最终验收。

题库覆盖事实、两/三跳、逆向、交集、歧义、实时及资料缺失。当前固定指南未人工确认真实矛盾题，因此不捏造冲突来源；冲突处理在 `tests/test_integrity.py` 的明确合成场景中验证。人工添加真实冲突题时需保留相互矛盾的完整证据。

源标注与题库构建脚本为 `scripts/build_evaluation.py`，需要本地 `data/reference-source.json`。脚本只维护题库，不是评测时在线生成标签。标注中未把“有一条引用”当作完整证据。
