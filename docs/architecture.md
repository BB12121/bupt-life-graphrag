# 后端架构

本项目使用模块化单体，SQLite 是事实与原文的持久来源。进程持有数据目录文件锁，业务操作使用可重入锁；不支持多 worker。模型只在首次编码时加载，正常问答不会调用外部生成模型。

| 模块 | 责任 |
|---|---|
| `api.py` / `models.py` | HTTP、OpenAPI、请求与响应数据类型 |
| `source.py` | 固定上游、完整 SHA、完整文件清单、正文下载 |
| `parsing.py` | 标题层级、原文片段、行号、证据稳定 ID、校区范围 |
| `knowledge.py` / `resources/` | 整段原文匹配、关系类型检查、人工审核事实与别名 |
| `embedding.py` | BGE CPU 模型、真实 tokenizer、512 维规范化向量 |
| `retrieval.py` | BM25、余弦、RRF、NetworkX MultiDiGraph、有界路径执行 |
| `qa.py` | 校区与实体澄清、规则规划、交集、证据检查、摘录答案与拒答 |
| `storage.py` / `service.py` | SQLite 原子发布、缓存、生命周期、串行同步与问答 |
| `cli.py` / `llm.py` | 本地管理、人工审核、可选本地小模型候选 |

## 增量同步

1. 将 ref 解析为完整 SHA；仓库固定为指南上游。
2. 获取完整文件树并排除首页、贡献说明、致谢。任何读取失败、截断文件树或空清单均终止同步。
3. 逐文档比较内容哈希。未变化且配置一致的文档复用已解析片段、事实和候选。
4. 对变化正文使用原始行号分块，屏蔽代码块、脚本、注释和独立图片。正文每块不超过 400 个实际 tokenizer token；标题与正文联合过长时仅编码正文。
5. 只有“完整段落 + 标题 + 文件路径”仍一致的审核事实继续有效。不确定段落进入 pending。
6. 向量缓存键包含模型名称/版本与输入文本哈希。删除、移动或换行不使未变文本重复编码。
7. 从准备完成的事实集合构建内存图与索引。共享事实聚合多条来源证据，失去一个来源不删除其他来源支持的事实。
8. 一个 SQLite 事务写入向量缓存与新快照，然后替换当前内存索引。失败时保持旧快照；历史正文仍可通过 SHA 读取。

初始图资源共 28 条已核对规则，并非 28 篇文档。自动候选不是已成立事实。删除文档、改名、修改段落都会撤回相应旧证据。更改审核规则或模型标识也会触发新版本。

## 查询与证据

校区先过滤：明确校区保留该校区与 shared；unknown 不自动当作通用资料。正文显式提及另一校区时不会盲目继承目录。明确跨校区对比暂不支持。

向量和 BM25 各取 Top10，片段 ID 上进行 RRF。图题遵守固定方向和关系序列，最多 3 跳。逆向遍历只改变路径顺序，不改变边的事实方向。交集按两分支末端实体 ID 取交集，证据预算以完整证明组为单位。

必要证据以唯一引文字符数控制，总预算 12000；图证据不受文本 Top10 限制。证据超预算或搜索未完成时给出 `partial/search_truncated`，不输出残缺路径。普通文本回答最多显示三段经过相关度和答案字段检查的原文。

相同段落由不同文件支持时可以复用向量，但每个来源有自己的证据 ID。ID 中包含固定提交，原文 URL 带 commit 及 1 起始、两端包含的行号。

## 范围与扩展点

默认问答是可溯源的规则/摘录方式。语义判断不可能由当前启发式保证完全正确，因此单独保留人工评测字段。标记冲突由人工审核提供 `conflict_key/decision`，尚无自动通用矛盾检测。

后续可以在稳定的 `QAResponse` 之上加入严格受证据约束的措辞模型、更多经审核关系模板和授权控制。优先扩充原文事实与测试题，不应为了增加图边而把共现或超链接当作关系。
