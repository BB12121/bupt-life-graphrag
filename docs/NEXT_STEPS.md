## 3. 各任务的验收标准

交付：书面的范围结论。公开仓库只保留必要结论，不上传私人聊天或个人信息。

### T1：让量化小模型实际运行

- [ ] 选定并运行设计中的 Qwen2.5-1.5B-Instruct GGUF Q4_K_M，或记录符合课程范围的替代模型。
- [ ] 固定模型来源、版本/文件校验值、量化规格、llama.cpp 版本、启动命令、上下文长度及硬件配置。
- [x] 接通现有 `BUPT_LLM_BASE_URL`、`BUPT_LLM_MODEL` 和 `suggest` 命令，保留真实输入与输出样例。（远程模型候选调用，见 t1-t4-validation.md。）
- [x] 验证无关系、否定、二选一条件、适用阶段、超时、非法 JSON 等情况，不把模型输出直接作为事实发布。（阶段案例保守漏抽，故障采用注入测试。）
- [x] 确认离线或失败时已有知识库仍能运行，错误提示明确。

- [ ] 审核前检查来源定位、关系方向、实体类型、校区、否定、条件和阶段；语义不确定的候选不能自动通过。
- [x] 新增独立测试段落，证明新事实不需要先写入初始事实资源，便能进入“抽取→审核→发布”的流程。

## 4. 领取任务后从哪里开始

先看 [README](../README.md)、[整合运行说明](integration.md) 和 [小组合作约定](../CONTRIBUTING.md)。使用自己的分支，通过 PR 合并；提交消息或 PR 描述注明任务 ID。

已初始化本地知识库后，可使用现有命令开始知识审核。**以下管理命令应在 API 停止后运行，或使用独立数据目录；API 和 CLI 不能同时占用同一个知识库。**

```powershell
.venv/Scripts/python.exe -m bupt_rag.cli pending --output data/pending.json

# 启动并验证本地 llama.cpp 后，选取 pending 中真实的 ID。
$env:BUPT_LLM_BASE_URL='http://127.0.0.1:8080/v1'
$env:BUPT_LLM_MODEL='qwen2.5-1.5b-instruct'
.venv/Scripts/python.exe -m bupt_rag.cli suggest CANDIDATE_ID --output data/draft.json

# 人工核对并编辑草稿为 reviewed.json，再导入与发布。
.venv/Scripts/python.exe -m bupt_rag.cli approve data/reviewed.json
.venv/Scripts/python.exe -m bupt_rag.cli sync --ref 417fc690834fbc4406f48e503f5ef1f832d495db
```

上面的命令是当前已有功能，不代表批量抽取已经实现。`data/` 被 Git 忽略；跨成员共享审核成果时，应按 [review.md](review.md) 整理可审阅资源并提交，不能只提交一个指向本地文件的说明。

建议推进顺序：T0 确认范围，同时 T1 部署模型、T6 准备评分规范；随后 T2 与 T3 分批交付，T4/T5 跟进；最后冻结代码和资料，完成 T6/T7 实测、T8 报告。
